# KOReader 自适应自动翻页

![Lua 5.1](https://img.shields.io/badge/Lua-5.1-blue) ![License: MIT](https://img.shields.io/badge/License-MIT-green) ![KOReader 用户补丁](https://img.shields.io/badge/KOReader-user%20patch-orange)

[English](README.md) · **简体中文**

> 一个单文件 KOReader 用户补丁：从你自己的手动翻页节奏里学出间隔，再把这个间隔交给自动翻页，而不是让你去猜一个秒数。

KOReader 自带的 **AutoTurn** 插件按固定秒数翻页。本补丁用「实测值」替换这个固定猜测，且完全不修改 KOReader 源码。

---

## 设计初衷

AutoTurn 要求你填一个秒数。这个数字只能靠猜，而且怎么猜都容易出问题：

- **太短** —— 还没读完就翻页，得不停往回翻；
- **太长** —— 早读完了，却要干等它翻。

阅读速度是因人而异的，同一个人在一次阅读里也会变：进入状态后越读越快，累了或者遇到密集版面又会慢下来。一个写死的数字跟不上这种变化，而靠试错去调也很折腾——改一次设置、读一会儿、再改一次。

所以这里的思路很直接：**让阅读器自己量**。观察一段正常的手动翻页，只保留真正反映阅读节奏的间隔，取平均，再把结果交回 AutoTurn。你不需要猜任何数字。

由此引出几个设计取舍：

| 取舍 | 理由 |
| --- | --- |
| **全局单值，不按书隔离** | 阅读速度属于读者，不属于某本书。所有书共用一个学习值，打开新书不需要重新训练。 |
| **零侵入** | 以 `2-` 开头的用户补丁，只在运行时挂钩。不改 KOReader 源码、不写全局变量、不建目录、不写数据文件、不依赖 `lfs`。删掉文件即完全还原。 |
| **不打扰，直到你主动开启** | 开书时没有任何弹窗。补丁只在你**手动开启自动翻页**的那一刻介入。 |
| **合理样本一律保留** | 只剔除真正的异常值，不做近期加权：人往往越读越快，给近期样本加权会把结果往「翻页过快」拉。取全期均值，保留从容、真实的节奏。 |
| **失败即静默** | 所有 `require`、接口探测、界面调用、hook 都包在 `pcall` 里。符号缺失或 KOReader 版本不同，只记一条日志然后让开，绝不影响 KOReader 启动。 |
| **尊重原生电源管理** | `PluginShare.pause_auto_suspend` 由 AutoTurn 原生 `_start()` / `_unschedule()` 成对维护，补丁自己绝不单边写这个标志；采集期与取消后设备都能正常自动待机。 |

## 功能说明

**触发方式。** 当你在菜单里把自动翻页从**关 → 开**时，补丁先关闭设置菜单、弹出间隔选择框——选完任一选项后直接回到阅读页，不停留在设置页面；"手动设置"也只显示一个输入框，不会与菜单叠成两个弹窗。**开 → 关**直接关闭，不再弹出原生的「设置时间 / 禁用」选择框。开书全程静默。

**间隔选择框**提示「即将开启自动翻页，请设置翻页间隔：」，提供四个选项：

| 选项 | 行为 |
| --- | --- |
| 当前间隔 | 有学习值时显示「当前间隔：X 秒/页」并按该值开启，提示当前间隔 3 秒后自动关闭；无学习值时显示「当前间隔：暂无数据」，点击后提示「暂无当前数据，请选择自动设置或手动设置」，3 秒后重弹选择框引导设置，不开启自动翻页 |
| 自动设置 | 从你的手动翻页中重新学习间隔，同样先弹 3 秒提示再开始采集 |
| 手动设置 | 输入 3~120 的整数秒；输入非法会提示并可重新输入 |
| 取消 | 不开启自动翻页，不做任何改动 |

**学习流程**

1. 先弹一个 **3 秒页面提示**「正在学习翻页节奏，请正常手动翻页。」。此时自动翻页已挂起、且不计样本——提示还停在屏幕上时的点击不会被记进去。
2. 提示关闭后正式开始采集。自动翻页保持关闭，你像平时一样手动翻页。
3. 采够 **40 个有效间隔**即结束；或读满 **20 分钟且已有 15 个有效样本**也提前结算——慢速读者不必等满超时；另设 **30 分钟**最终兜底，三者先到先结算。
4. 学习值写入设置，自动翻页按该间隔开启。
5. 若有效数据不足，则**不覆盖**已有学习值、**不开启**自动翻页，仅提示 3 秒后自动关闭；可再次开启并「自动设置」重试。
6. **采集途中想放弃**：再次点击自动翻页菜单项（或开关）即取消本次采集，自动翻页保持关闭、不写入任何数据，之后可重新开启。

### 间隔是怎么算出来的

只剔除**异常**间隔，合理范围内的值全部保留，最后对整段采集取平均。

| 方向 | 规则 | 针对什么 |
| --- | --- | --- |
| 特别大 | `间隔 > 中位数 × 3` | 离开、走神、长时间中断 |
| 特别小（采样阶段） | `间隔 < 6 秒` 不入池，但仍推进计时基准 | 误触、连翻，例如 5 秒的双击 |
| 特别小（统计阶段） | `间隔 < max(6 秒, 中位数 × 0.4)` | 相对你自身节奏异常快的间隔 |

刻意**不做**双侧 IQR、不丢阅读碎片段、不做近期加权：前两者会把「读得慢」的合理样本删掉、把均值压小，后者会跟着越读越快的趋势把均值拉小，结果都是翻页太快。最终值会 clamp 到 3~120 秒并四舍五入。

只有**相邻向前翻页**才计入。跳转、回翻、目录/书签/搜索定位、连续快翻的翻找模式、以及自动翻页产生的翻页都会被排除。计时使用 KOReader 的单调时钟，休眠唤醒不会让样本被墙上时间跳变污染。

### 电源与休眠唤醒行为

休眠唤醒是所有定时类补丁最难处理的场景，补丁在这部分刻意保守：

- **电源标志全程成对，锁屏不再被卡住。** 补丁不直接写 `PluginShare.pause_auto_suspend`。开启走 AutoTurn 原生 `_start()`（置 true），停止走 `_unschedule()`（清 false）。关键在 `onSuspend` 时补丁会**主动调用原生 `_unschedule()`**，而不依赖 AutoTurn 自己的 `onSuspend` 处理器——AutoTurn 通过 `event_hook("InputEvent")` 注册，广播的 `Suspend` 事件在某些版本/插件组合下未必送达它，标志就会卡在 true，导致设备一直无法锁屏、停止自动翻页后超过设定时间也不自动待机。这次主动调用与原生调用幂等。
- **唤醒时恢复自动翻页。** 若锁屏前自动翻页处于开启状态，补丁在挂起时记下它；`onResume` 时用原生 `_start()` 恢复，让待机标志与翻页任务一起重建。采集/等待阶段则刻意保持自动翻页挂起，唤醒不会在训练中途重启翻页。
- **两套时钟，一个权威截止时刻。** KOReader 的 `scheduleIn` 基于 `CLOCK_MONOTONIC`，休眠期间不走。因此补丁以「含休眠的墙上单调时钟」`UIManager:getElapsedTimeSinceBoot()` 算出的截止时刻为准，判断页面提示与 30 分钟兜底超时；定时任务只作为「到点叫醒复核」的触发器。锁屏超过 30 分钟会在唤醒时立即结算，不会拖成一小时，跨休眠的间隔也不会计入样本。
- **采集期能正常锁屏。** 采集期间 `pause_auto_suspend` 为 false，设备可以照常锁屏；`onSuspend` 撤销补丁定时并清空计时基准，`onResume` 按剩余时长幂等重建（不依赖挂起事件的记账，事件丢失也有兜底），若截止时刻已过则立即结算退出。跨休眠的间隔绝不会被计入样本。
- **不留幽灵任务。** 开新书、关文档、换书、中止、结算、休眠，都会无条件清理全部定时任务句柄。
- **可重入。** AutoTurn 的 `_schedule()` 会同步派发翻页并重新进入事件处理（例如自动翻页被菜单打断）。补丁用计数而非布尔标记这段窗口，嵌套调度不会把自动翻页误判成手动样本。
- **内存随书释放。** 关书时还原全部 hook 并释放对 ReaderUI 实例的引用，关闭的书（含其渲染文档）不会在浏览文件管理器期间被补丁钉在内存里。事件包装避免逐事件分配，页面事件只在采集期处理——日常翻页状态下补丁零开销。
- **挂起与唤醒全程可观测。** 无论补丁处于什么状态，每次挂起/唤醒事件都各打一行 `aat:` 日志，真机日志可直接确认事件确实送达补丁。
- **用完即休眠。** 学到或设好间隔后，补丁不再保留任何样本与计时状态，进入休眠，直到你再次开启自动翻页才唤醒。休眠态下只有四类低频生命周期事件（开书、关书、挂起、唤醒）会进入补丁；日常翻页、跳转、重排在事件入口即被短路——不调时钟、不打日志、不改状态。因此正常阅读时补丁几乎零开销。再次开启自动翻页是唯一的唤醒途径，而这条路走的是菜单回调包装、不经过事件处理，所以唤醒始终有效。

### 日志排查

补丁所有日志都以 `aat:` 为前缀，格式为紧凑的 `键=值`，便于快速扫读。排查锁屏/唤醒相关的卡死时，以下几行最有用：

| 日志行 | 含义 |
| --- | --- |
| `aat: suspend received phase=...` | 补丁已收到系统挂起事件，并主动停止自动翻页、清除电源标志 |
| `aat: resume received phase=...` | 补丁已收到唤醒事件 |
| `aat: resume, autoturn restored via native _start` | 锁屏前自动翻页开着，唤醒后已通过原生 `_start` 恢复（标志重建） |
| `aat: hooks installed / hooks detached` | 开书挂载 hook / 关书还原 hook |
| `aat: autoturn enabled sec=...` | 自动翻页已按该间隔开启 |
| `aat: autoturn disabled (native dialog skipped)` | 你在菜单里点关闭，补丁跳过原生选择框直接关闭并清待机标志 |
| `aat: collection done reason= ... learned=...` | 采集完成并写入学习值（`reason=` 后为 `enough`=采够40个、`adaptive`=满20分钟且样本够、或 `timeout`=30分钟兜底） |
| `aat: collection failed reason=... ... stays=off` | 有效样本不足，未开启自动翻页（不按任何默认值开启） |

想零改动验证「锁屏卡死是否与自动翻页有关」：在 AutoTurn 菜单里先**关闭**自动翻页再锁屏，解锁后再**开启**。若不再卡死，即可确认问题出在「自动翻页开启状态下休眠」这条路径。（自动翻页菜单项由 `addToMainMenu` 生成，补丁拦「关→开」弹选择、「开→关」直接关闭。）

## 安装

1. 把 `2-adaptive-autoturn.lua` 放到 `koreader/patches/`。
2. 保持文件名以 `2-` 开头——这表示在 UIManager 就绪后的 late 阶段加载。
3. 重启 KOReader，确认已启用 **AutoTurn** 插件，且处于分页视图（非滚动模式）。

请勿与其他同样包裹 AutoTurn 的补丁同时使用，否则 hook 会叠加。

## 卸载

删除该文件（或改名为 `.disabled`）并重启即可。不会留下源码改动、数据文件或全局状态。

## 参数配置

所有可调项都在文件顶部的 `CFG` 表里，改完重启 KOReader 生效。

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `setting_key` | `adaptive_autoturn` | 存于 `G_reader_settings` 的设置项名 |
| `hint_timeout` | `3` | 页面提示停留秒数，关闭后才开始采集 |
| `target_samples` | `40` | 采够多少个有效间隔即结束 |
| `train_timeout_min` | `30` | 兜底超时（分钟） |
| `min_interval` | `2` | 小于此值计入「翻找模式」判定 |
| `abs_min_keep` | `6` | 绝对下限，更小的间隔绝不入池 |
| `max_interval` | `300` | 可记录的最长间隔 |
| `burst_count` | `3` | 连续快翻多少次触发计时重置 |
| `min_samples` | `8` | 结果有效所需的最少样本数 |
| `min_after_trim` | `5` | 剔除异常值后剩余样本下限 |
| `outlier_factor` | `3` | 上界＝中位数的倍数 |
| `small_outlier_ratio` | `0.4` | 下界＝中位数的比例 |
| `min_sec` / `max_sec` | `3` / `120` | 学习值 clamp 区间 |
| `adaptive_min_minutes` | `20` | 采满这么久且样本够即提前结算（慢速读者无需等满超时） |
| `adaptive_min_samples` | `15` | 提前结算所需的最少有效样本数 |
| `suspend_sec` | `86400` | 采集期用于挂起自动翻页的间隔 |

## 数据与隐私

唯一的持久状态是 `G_reader_settings.adaptive_autoturn` 中的一项，由 KOReader 自己写进 `settings.reader.lua`：

```lua
{
  learned_sec   = 42,   -- 学习到的间隔（秒）
  trained       = true, -- 是否已有有效学习值
  last_duration = 30,   -- 本次训练所用兜底超时（分钟）
}
```

补丁不创建目录、不写文件、不上传任何数据。原始翻页间隔只存在于采集期间的内存中，结算后即丢弃。若想清除学习值，删除 `settings.reader.lua` 里的 `adaptive_autoturn` 项即可。

开启自动翻页时，补丁还会更新 AutoTurn 自身的 `autoturn_timeout_seconds` / `autoturn_enabled` 设置，并重新挂上它的 `onResume` 回调。这些属于 AutoTurn 原生状态，不是补丁额外创建的数据。

## 兼容性与限制

- 纯 **Lua 5.1**，零全局写入。
- 运行时按 KOReader 真实符号探测（`ReaderReady`、`PageUpdate`、AutoTurn 字段与 `_schedule` / `_unschedule` / `_start`、`UIManager:getElapsedTimeSinceBoot()`、`onSuspend` / `onResume`、各类 widget），不硬编码接口。未来版本若内部结构变化，补丁会检测到不匹配并静默让开，而不是让 KOReader 起不来。
- **仅支持分页视图**，切换到滚动模式会中止采集并提示。
- 学习值是全局的。如果漫画与密集文字的阅读速度差别很大，这类场景可用「手动设置」。
- 尚未覆盖所有设备与 KOReader 版本组合，欢迎反馈具体固件 / 插件版本的兼容性。
- **连续点击保护**：补丁同一时刻只保留一个自己的弹窗，弹新的选择框/输入框前会先关掉上一个，避免快速连点堆叠出多个窗口与虚拟键盘。若你装了第三方输入法插件（如 `pinyin_enhancement`），已知它在中文拼音输入时可能与 KOReader 输入框冲突导致崩溃（异常在 `inputtext.lua addChars(nil)`，与本补丁无关）；本补丁的连点保护可显著降低触发概率，但彻底解决需更新/停用该输入法插件，或在手动设置时切换到英文/数字键盘。
