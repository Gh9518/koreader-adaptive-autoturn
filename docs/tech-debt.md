## TD-1 样本采集上限的显式硬约束（低优先，行为相关，未改）
- 现状：样本数组无独立长度上限，依赖 `should_finish_early()` 在 `n >= target_samples(40)` 时立即结算来终止增长。由于写入与判定在同一同步调用内（写入后立刻判定），实际上不会超过 40，是有界的。
- 可能改进：在 `S.samples[#S.samples+1] = gap` 前加一道 `if #S.samples >= CFG.target_samples then ... end` 显式封顶，作为防御式双保险。
- 未改原因：会引入一条新的提前返回分支，需配套新增测试用例；当前逻辑已被 212 用例覆盖且数学上有界，改动收益低于风险。若未来加入异步写入或第三方事件注入，应重新评估。

## TD-2 结算统计的三趟遍历可合并（微优化，未改）
- 现状：`compute_learned` → `trim_outliers` 内部 `sorted_copy`（1 趟拷贝 + 排序）→ 过滤遍历（1 趟）→ `mean`（1 趟）。
- 可能改进：中位数与均值可在单趟中累计，省去 `kept` 中间数组。
- 未改原因：样本上限仅 40，三趟遍历开销可忽略；合并会降低代码可读性、增加统计口径出错风险，违反「行为一致性优先」。基准显示结算为低频事件（一次训练一次），非热路径。

## TD-3 enable 开关探测的重复列表（可读性，未改）

- 可能改进：合并为单一带方向参数的探测函数。
- 未改原因：属结构重构，与内存/稳定性目标无关，且测试已覆盖两种方向；留待后续专门重构。
